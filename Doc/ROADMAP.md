---

## 한 줄

**P0:** 외부에서 점검 파이프라인을 한 번 돌리고, 필터 → AI 보고서(또는 fallback) → MinIO(S3) `reports/` `logs/` `collects/`까지 끝낸다.  
**P1:** 주기 모니터 + Discord 직접 알림.

구현 순서 (`Plan.md` 8.0): SSH → Pipeline(수집·보고서 제외) → Collector → Filter → Reporter → Notify(점검) → Monitor

---

## 단계 개요

소프트웨어 버전은 `버전별-로드맵.md`와 1:1이다.


| 단계     | 버전     | 이름     | 우선    | 완료하면                                            |
| ------ | ------ | ------ | ----- | ----------------------------------------------- |
| **M0** | v0.1.0 | 뼈대     | P0 일부 | CLI로 SSH 원격 실행, 실행 ID·이력이 남는다                   |
| **M1** | v0.2.0 | 코어 점검  | P0    | Docker 종료 → DNF → reboot → 재연결 → 재기동 → 헬스까지 E2E |
| **M2** | v1.0.0 | 관측·보고서 | P0    | 로그 필터 + AI/fallback + MinIO 3경로. **P0 완료**      |
| **M3** | v1.1.0 | 모니터    | P1    | 무응답 감시, Discord 알림, 스케줄 상시 운용                   |


캘린더 시기는 작업 리듬에 따라 조정한다. 참고: 하루 6시간·주 5일이면 M1까지 약 3~4주, M2까지 약 6~8주, M3까지 약 7~9주.

| 할 일                                                      | Plan        | FR    |
| -------------------------------------------------------- | ----------- | ----- |
| Go 모듈, `cmd`, 설정 로드 (YAML, 시크릿은 env)                     | 5.2, NFR-02 | —     |
| SSH key 실행, timeout, stdout/stderr/exit code             | 8.1         | FR-01 |
| 실패 분류: `auth_failed`, `host_unreachable`, `vpn_required` | 8.1         | FR-01 |

| `--dry-run` (원격 쓰기 없이 단계만 출력)                            | —           | —     |


**완료 기준**

- 단위 테스트는 SSH mock. 실서버는 읽기 전용 프로브만

**아직 안 함:** Docker stop, DNF, reboot, 보고서

## M1 — 코어 점검 파이프라인 (v0.2.0)

**목표:** `Plan.md` 2.2 「코어 점검」을 만족한다.


| 할 일                                         | Plan | FR           |
| ------------------------------------------- | ---- | ------------ |
| Pipeline 오케스트레이션, 단계 실패 시 **즉시 중단** (롤백 없음) | 8.2  | FR-12        |
| Docker 종료·기동 순서 **설정 파일만** (하드코딩 금지)        | 8.2  | FR-02, FR-05 |
| `sudo dnf -y update`                        | —    | FR-03        |
| reboot 후 backoff SSH 재연결, 부팅 완료 대기          | 8.1  | FR-04        |
| Collector: 리소스, 서비스·포트 헬스                   | 8.3  | FR-08        |
| sudo allowlist                              | 8.1  | NFR-02       |


**완료 기준**

- 한 번의 트리거로 종료 → DNF → reboot → 재연결 → 재기동 → 헬스체크가 끝난다
- 실서버 검증은 읽기 → Docker 소수 → 전체(점검 창) 순

**아직 안 함:** AI, MinIO 업로드, 로그 필터 완성, Discord, Monitor

## M2 — 수집·필터·보고서 (v1.0.0, P0 완료)

**목표:** `Plan.md` 2.2 「관측·보고서」+「실행 방식」을 만족한다.


| 할 일                                                           | Plan     | FR            |
| ------------------------------------------------------------- | -------- | ------------- |
| boot / dnf / fail2ban / **secure** raw log 수집                 | 8.3, 8.4 | FR-06         |
| 카테고리별 include/exclude 키워드                                     | 8.4      | FR-07         |
| 줄 배열 + 인덱스 + fingerprint map으로 중복 합치기 (큐·트리 없음)               | 8.4      | FR-07, NFR-06 |
| 종류별 AI 입력: boot 실패, dnf 이상+패키지 요약, fail2ban Ban, secure 스캔/실패 | 8.4      | FR-07         |
| AI 보고서 초안, 실패 시 템플릿 fallback                                  | 8.5      | FR-09         |
| 재기동·헬스 **이후** MinIO(S3)에 `reports/` `logs/` `collects/` 업로드   | 8.5      | FR-10, FR-12  |
| CLI 수동 실행 + 스케줄(cron 등)                                       | 8.2      | FR-11         |
| (선택) 점검 시작/완료/실패 Discord — Notify만, Monitor 없음                | 8.6      | —             |


**완료 기준**

- 필터된 입력으로 보고서가 `reports/`에, 실행 로그가 `logs/`에, 수집 아카이브가 `collects/`에 올라간다. AI 실패 시에도 fallback 보고서가 남는다
- 스케줄로 unattended 점검 1회가 가능하다

이 단계가 끝나면 **P0(MVP) 종료**.

**목표:** `Plan.md` 2.2 「모니터링 (후속)」.


| 할 일                                                           | Plan     | FR    |

- Notify 실패는 로컬 로그(및 가능하면 MinIO `logs/`), Pipeline/Monitor는 계속된다

## 이 로드맵에 넣지 않는 것 (`Plan.md` 2.3)

- Pipit-hub `!status` · 대시보드
- 전원/VM 프로브, 알림 원인 세분화
- 다중 서버·테넌트
- 점검 실패 자동 롤백
- 오탐 방지를 위한 서버 다중화
- 상용급 메트릭·대시보드
- journal 보완 수집, 로그 템플릿 클러스터 — P0 이후 여유 있을 때
- oCIS / Google Drive를 gostodian 산출물 저장소로 쓰는 것

## 의존 관계

```
M0 SSH·CLI                          v0.1.0
 └─ M1 Pipeline + Collector(헬스)   v0.2.0
      └─ M2 Filter + Reporter + MinIO(S3) + 스케줄   v1.0.0  ← P0
           └─ M3 Monitor + Discord 이상 알림        v1.1.0  ← P1
```

Notify를 M2에서 점검 이벤트용으로 먼저 만들어 두면 M3 Monitor가 같은 모듈을 재사용한다.
