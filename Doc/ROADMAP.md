# Gostodian 로드맵

작성일: 26.10.12

---

## 1. 한 줄 개요

- 점검 머신의 `gostodian`이 VPN·SSH로 홈랩에 접속해 서비스 정지 → `dnf update` → 재부팅 → 서비스 기동 → 로그 수집 → 보고서 업로드까지 수행하고, 결과는 점검 머신이 직접 Discord로 알린다.
- 홈랩은 허용된 동사만 통과시키는 게이트(`gostodian-gate`)만 둔다.
- Gostodian의 목적은 서버 점검 자동화와 (LLM API를 이용한 보고서 작성시)토큰 감소이다.

## 3. 현재 구현 범위와 수정 범위

**구현**

- YAML 설정과 시크릿 파일 읽기
- `knownhosts`로 호스트 키를 확인하는 SSH 접속. 실패 분류는 `auth_failed`, `host_unreachable`
- 실행 ID, 구조화 로그, 단계 이력
- CLI `version`, `config validate`, `exec`

**수정**

- `gostodian exec` → `gostodian run`
- 인자 없이 기동 후 즉시 재시작 → `docker compose run --rm gostodian run`으로 1회 실행
- 이력 디렉터리 `logs/` → 볼륨. 읽기 전용 컨테이너에서는 이력 기록 불가

**추가**

- `gostodian key init`: 키 파일 없을 때만 ed25519 키 생성, 공개키 출력
- 접속 실패 분류에 호스트 키 불일치, VPN 미연결 추가

## 4. 버전별 구현사항

### v0.1.0 (접속)

**구현**

- `gostodian run`: 수동 실행. 컨테이너는 `docker compose run --rm gostodian run`
- 시크릿 본문은 `secrets/` 파일(컨테이너는 `/run/secrets`). env에는 경로만
- `gostodian key init`: 키 파일 없을 때만 ed25519 키 생성, 공개키·fingerprint 출력. 인증 실패 시 재생성 없음
- 호스트 키는 `knownhosts.New`로 고정
- 접속 실패 분류에 호스트 키 불일치, `vpn_required` 추가
- 실행 이력은 볼륨

**완료 기준**

- `run` 한 번의 SSH 결과는 이력
- 홈랩 꺼짐 또는 VPN 끊김 시 실패 종류는 이력
- 키 파일이 있으면 `key init`은 키 유지

### v0.2.0 (게이트)

**구현**

- `gostodian-agent` → `gostodian-gate`
- `authorized_keys`는 `restrict,from="<점검머신 VPN IP>",command="/usr/local/bin/gostodian-gate"`
- 게이트 입력은 `SSH_ORIGINAL_COMMAND` = `동사 [이름]`. 동사는 고정 목록, 이름은 홈랩 허용 목록과 정확히 일치할 때만 통과. 그 외는 거부와 거부 로그
- 동사 `status`(호스트 기본 정보), `boot-id`. 읽기 전용

**완료 기준**

- `run`의 게이트 `status` 실행, 결과는 이력
- 목록 밖 동사, 허용 목록 밖 이름, 추가 인자는 거부

### v0.3.0 (알림)

**구현**

- Discord 웹훅: 점검 시작·완료·실패, 접속 실패 분류. 원문 로그 제외
- 전송 실패 시 로컬 로그만. 점검은 계속

**완료 기준**

- `status` 결과는 Discord
- 홈랩 꺼짐 또는 VPN 끊김에도 분류된 실패 알림

### v0.4.0 (유지보수)

**구현**

- 서비스 정지 순서는 점검 머신 설정의 목록으로 관리. 기동은 역순. 서비스 이름은 코드에 미포함
- 게이트에는 건드려도 되는 서비스 이름 허용 목록만
- 동사 `stop <서비스>`, `start <서비스>`. 서비스마다 결과 확인
- 재부팅 뒤 자동 기동을 막는 정지 방식 (`down` 또는 재시작 정책 통일)
- 게이트 sudo 명령은 인자까지 고정해 sudoers에 등록. `docker`, `dnf *`, `systemd-run`은 미허용
- 동사 `update`: `systemd-run` 일회성 유닛으로 `dnf -y update` 실행, `update-status`로 폴링
- 동사 `reboot`: 재부팅 전 `boot_id` 저장, 지수 백오프 재접속 후 `boot_id` 변경 확인. 제한 시간 초과 시 알림
- 동사 `health`: 컨테이너 기동 여부, 포트 Listening
- 모든 단계에 timeout. 실패 시 즉시 중단과 알림. 자동 롤백 없음

**완료 기준**

- 한 번의 실행으로 정지 → `dnf` → 재부팅 → 재접속 → 역순 기동 → 헬스체크
- `boot_id` 불변 또는 제한 시간 내 미복귀는 실패 처리와 알림
- 실서버 점검 창에서 재부팅까지 검증

### v0.5.0 (수집·필터)

**구현**

- 동사 `collect-logs <종류>`: dnf, boot, secure, fail2ban. 재부팅 뒤, 서비스 기동 전에 수집
- 동사 `resources`: RAM, CPU, Storage
- 일부 수집 실패 시에도 나머지 계속, 빠진 항목은 기록
- 필터: 카테고리별 include/exclude, 줄 인덱스 + fingerprint로 중복 합치기, 길이 상한. 규칙은 설정 파일 (`Docs/Plan.md` 8.4)
- 리댁션: 호스트명, IP, 계정, 토큰
- 이상 여부는 규칙으로 판정

**완료 기준**

- 필터와 리댁션의 골든 테스트
- 매칭 0건 카테고리는 「이상 없음」
- 실서버에서 네 종류 로그와 리소스는 실행 ID 단위

### v1.0.0 (보고서·업로드·스케줄)

**구현**

- AI 보고서 초안. 로그는 구조화된 필드, 경계 명시. AI 실패 시 고정 템플릿. LLM 출력은 실행 대상 아님
- MinIO 업로드: `reports/` 보고서, `logs/` 실행 로그, `collects/` 수집 아카이브. MinIO 재기동·헬스체크 통과 후에만
- SSE, PutObject 전용 키. 버킷과 프리픽스는 설정
- 업로드 실패 시 로컬 보존과 알림
- 게이트 거부 로그는 보고서. 거부 시 별도 알림
- Discord 완료 알림에 판정 요약과 보고서 위치
- 스케줄 실행은 점검 머신 타이머가 `gostodian run`을 한 번 실행. 상시 프로세스 스케줄러는 두지 않음. 수동 실행은 유지

**완료 기준**

- 보고서·실행 로그·수집 아카이브는 같은 실행 ID로 MinIO 업로드
- AI 실패 시에도 보고서와 알림
- MinIO 미기동 시 산출물은 로컬, 알림
- 스케줄로 한 번 이상 끝까지 실행

**별도. 이 저장소 밖**

- `gostodian-svc`는 별도 저장소에서 구현하고, 홈랩 `/usr/local/libexec/gostodian-svc`에 둔다
- 이 저장소의 게이트는 그 경로를 호출만 한다. v1.0.0 실서버 확인 전에 필요하다
- 호출은 `down`, `start`, `update`, `update-status`, `reboot`, `collect-logs`, `health`, `resources`

### v1.1.0 (감시)

**구현**

- 상시 프로세스의 주기 확인 (예: 5분)
- 서버: SSH 접속 여부. 서비스: 게이트 `health`, 필요하면 HTTP 응답
- 상태 변화 시에만 알림. 같은 알림은 쿨다운으로 억제. 복구 시 알림
- `run` 실행 중 감시 알림 억제

**완료 기준**

- 홈랩을 끄면 Down 알림, 켜면 복구 알림
- 같은 상태가 이어지는 동안 알림 반복 없음
- `run` 재부팅 중 감시 알림 없음

### 하지 않는 것

- 홈랩 상주 데몬, 홈랩 안의 알림 프로세스
- 게이트 밖의 임의 SSH 명령, 셸 문자열 조립
- 시크릿 본문을 env에 넣는 것, 호스트 키 검증을 끄는 것
- LLM 출력을 실행하는 것
- apt, Podman, 다중 서버, 대시보드
- 점검 실패 자동 롤백
- 전원·VPN 원인 세분화
- oCIS / Google Drive를 산출물 저장소로 쓰는 것

### v1.1.0 이후 후보

- `gostodian key rotate`: 키 교체와 만료 경고
- 서비스 순서는 의존성 그래프로 정의, compose `depends_on`은 기본값
- 단계 체크포인트에서 이어 하기
- 점검 시간 밖의 점검 계정 로그인 감지
- `journalctl -b -p err`로 커널·OOM 오류 보완
