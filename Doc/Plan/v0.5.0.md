# v0.5.0 (수집·필터) — 초안

상태: **초안**. 로드맵 v0.5.0 범위를 옮겨 적은 것이다. 세부 구현·일정은 확정 전이다. 구현은 실서버 테스트보다 먼저 진행하고, 미룬 확인은 4번에 둔다.

기준: `Doc/RoadMap_v1.md`의 v0.5.0  
출발점: v0.4.0  
일정: 26.11.1 (예정)

## 1. 목표

재부팅 뒤·서비스 기동 전에 로그와 리소스를 모으고, 필터·리댁션·규칙으로 이상 여부를 판정한다. 일부 수집이 실패해도 나머지는 계속하고, 빠진 항목은 기록에 남긴다.

## 2. 구현 내용

- 동사 `collect-logs <종류>`. dnf, boot, secure, fail2ban. 재부팅 뒤, 서비스 기동 전에 수집
- 동사 `resources`. RAM, CPU, Storage
- 일부 수집 실패 시에도 나머지 계속. 빠진 항목은 기록
- 필터. 카테고리별 include/exclude, 줄 인덱스와 fingerprint로 중복 합치기, 길이 상한. 규칙은 설정 파일
- 리댁션. 호스트명, IP, 계정, 토큰
- 이상 여부는 규칙으로 판정

## 3. 상세 구현 내용

### 3.1 `collect-logs`

**구현**

- 추가: 게이트 동사 `collect-logs <종류>`. 종류는 dnf, boot, secure, fail2ban
- 추가: `gostodian run`은 재부팅·재접속 뒤, 서비스 기동 전에 네 종류를 수집
- 유지: 셸 문자열 조립 없음. 종류는 고정 목록과 정확히 일치할 때만 통과

**완료**

- [x] 네 종류 로그가 실행 ID 단위로 수집됨
- [x] 목록 밖 종류는 거부되고 실행되지 않음

### 3.2 `resources`

**구현**

- 추가: 게이트 동사 `resources`. RAM, CPU, Storage
- 추가: 결과는 실행 이력과 수집 산출물에 남김

**완료**

- [x] RAM, CPU, Storage가 실행 ID 단위로 남음

### 3.3 부분 실패 계속

**구현**

- 추가: 한 종류 수집이 실패해도 나머지 종류는 계속
- 추가: 빠진 항목은 이력에 실패로 기록. 전체 점검을 그 이유로 즉시 중단하지 않음

**완료**

- [x] 일부 실패 후에도 나머지 수집이 이어짐
- [x] 빠진 항목이 이력에 남음

### 3.4 필터

**구현**

- 추가: 카테고리별 include/exclude
- 추가: 줄 인덱스와 fingerprint로 중복 합치기, 길이 상한
- 확인 필요: 로드맵의 규칙 설정 파일 위치(`Docs/Plan.md` 8.4 언급). 기본안은 점검 머신 설정 파일

**완료**

- [ ] 필터 골든 테스트 통과
- [ ] 길이 상한을 넘는 내용은 잘림이 기록됨

### 3.5 리댁션

**구현**

- 추가: 호스트명, IP, 계정, 토큰 가림
- 유지: 시크릿 본문과 웹훅 주소는 산출물·알림에 없음

**완료**

- [ ] 리댁션 골든 테스트 통과

### 3.6 규칙 판정

**구현**

- 추가: 필터·리댁션 뒤 규칙으로 이상 여부 판정
- 추가: 매칭 0건 카테고리는 「이상 없음」

**완료**

- [ ] 매칭 0건은 「이상 없음」
- [ ] 이상 판정이 실행 ID 단위로 남음

## 4. 테스트

실서버 없이 구현을 먼저 한다. 아래는 그 뒤에 확인할 목록이다. v0.4.0 확인을 먼저 끝내고 v0.5.0 확인을 한다. 둘을 한 실행에 합친 순서 확인은 4.4 마지막 항목에서만 한다.

### 4.1 v0.4.0 재부팅 없는 확인

`Doc/Plan/v0.4.0.md` 4.1. 재부팅 없이 게이트와 이력만 확인.

**대상**

- v0.4.0 3.2 게이트 허용 목록
- v0.4.0 3.3 `stop`, `start`
- v0.4.0 3.5 sudoers
- v0.4.0 3.8 `health`

**완료**

- [ ] 허용 목록 밖 이름, 추가 인자는 거부. 거부된 문자열은 실행되지 않음
- [ ] `stop`, `start` 결과가 서비스마다 이력
- [ ] sudo 명령은 등록된 고정 인자와 같음. `docker`, `dnf *`, `systemd-run`은 sudoers에 없음
- [ ] `health` 결과가 이력

### 4.2 v0.4.0 실서버 점검 창

`Doc/Plan/v0.4.0.md` 4.2. 수집을 끼우기 전에, 유지보수 한 사이클만 확인.

**대상**

- v0.4.0 3.1 정지 순서
- v0.4.0 3.4 재부팅 뒤 자동 기동
- v0.4.0 3.6 `update`
- v0.4.0 3.7 `reboot`
- v0.4.0 3.9 단계 실패

**완료**

- [ ] 한 번의 `gostodian run`으로 정지 → `dnf` → 재부팅 → 재접속 → 역순 기동 → 헬스체크
- [ ] 설정 목록 순서로 정지, 역순으로 기동
- [ ] 정지 뒤 재부팅해도 대상 서비스는 올라오지 않음
- [ ] `update` 진행이 `update-status`로 이력. 갱신 실패는 그 단계에서 중단
- [ ] `boot_id`가 바뀐 뒤에 기동. 불변이거나 제한 시간 안에 돌아오지 않으면 실패와 알림
- [ ] 중간 실패는 다음 단계로 가지 않고 알림
