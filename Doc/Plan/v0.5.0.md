# v0.5.0 (수집·필터) — 초안

상태: **초안**. 로드맵 v0.5.0 범위를 옮겨 적은 것이다. 세부 구현·일정은 확정 전이다.

기준: `Doc/RoadMap_v1.md`의 v0.5.0  
출발점: v0.4.0  
일정: 26.11.1 (예정)

## 1. 목표

재부팅 뒤·서비스 기동 전에 로그와 리소스를 모으고, 필터·리댁션·규칙으로 이상 여부를 판정한다. 일부 수집이 실패해도 나머지는 계속하고, 빠진 항목은 기록에 남긴다.

## 2. 구현 내용

- 동사 `collect-logs <종류>`. dnf, boot, secure, fail2ban. 재부팅 뒤, 서비스 기동 전에 수집
- 동사 `resources`. RAM, CPU, Storage
- 일부 수집 실패 시에도 나머지 계속. 빠진 항목은 기록
- 필터. 카테고리별 include/exclude, 줄 인덱스와 fingerprint로 중복 합치기, 길이 상한. 규칙은 설정 파일
- 리댁션. 호스트명, IP, 계정, 토큰
- 이상 여부는 규칙으로 판정

## 3. 상세 구현 내용

### 3.1 `collect-logs`

**구현**

- 추가: 게이트 동사 `collect-logs <종류>`. 종류는 dnf, boot, secure, fail2ban
- 추가: `gostodian run`은 재부팅·재접속 뒤, 서비스 기동 전에 네 종류를 수집
- 유지: 셸 문자열 조립 없음. 종류는 고정 목록과 정확히 일치할 때만 통과

**완료**

- [ ] 네 종류 로그가 실행 ID 단위로 수집됨
- [ ] 목록 밖 종류는 거부되고 실행되지 않음

### 3.2 `resources`

**구현**

- 추가: 게이트 동사 `resources`. RAM, CPU, Storage
- 추가: 결과는 실행 이력과 수집 산출물에 남김

**완료**

- [ ] RAM, CPU, Storage가 실행 ID 단위로 남음

### 3.3 부분 실패 계속

**구현**

- 추가: 한 종류 수집이 실패해도 나머지 종류는 계속
- 추가: 빠진 항목은 이력에 실패로 기록. 전체 점검을 그 이유로 즉시 중단하지 않음

**완료**

- [ ] 일부 실패 후에도 나머지 수집이 이어짐
- [ ] 빠진 항목이 이력에 남음

### 3.4 필터

**구현**

- 추가: 카테고리별 include/exclude
- 추가: 줄 인덱스와 fingerprint로 중복 합치기, 길이 상한
- 확인 필요: 로드맵의 규칙 설정 파일 위치(`Docs/Plan.md` 8.4 언급). 기본안은 점검 머신 설정 파일

**완료**

- [ ] 필터 골든 테스트 통과
- [ ] 길이 상한을 넘는 내용은 잘림이 기록됨

### 3.5 리댁션

**구현**

- 추가: 호스트명, IP, 계정, 토큰 가림
- 유지: 시크릿 본문과 웹훅 주소는 산출물·알림에 없음

**완료**

- [ ] 리댁션 골든 테스트 통과

### 3.6 규칙 판정

**구현**

- 추가: 필터·리댁션 뒤 규칙으로 이상 여부 판정
- 추가: 매칭 0건 카테고리는 「이상 없음」

**완료**

- [ ] 매칭 0건은 「이상 없음」
- [ ] 이상 판정이 실행 ID 단위로 남음
