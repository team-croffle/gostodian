# v0.5.0 (수집·필터) — 초안

상태: **초안**. 로드맵 v0.5.0 범위를 옮겨 적은 것이다. 세부 구현·일정은 확정 전이다. 구현은 실서버 테스트보다 먼저 진행하고, 미룬 확인은 4번에 둔다.

기준: `Doc/RoadMap_v1.md`의 v0.5.0  
출발점: v0.4.0  
일정: 26.11.1 (예정)

## 1. 목표

재부팅 뒤·서비스 기동 전에 로그와 리소스를 모으고, 필터·리댁션·규칙으로 이상 여부를 판정한다. 일부 수집이 실패해도 나머지는 계속하고, 빠진 항목은 기록에 남긴다.

## 2. 구현 내용

- 동사 `collect-logs <종류>`. dnf, boot, secure, fail2ban. 재부팅 뒤, 서비스 기동 전에 수집
- 동사 `resources`. RAM, CPU, Storage
- 일부 수집 실패 시에도 나머지 계속. 빠진 항목은 기록
- 필터. 카테고리별 include/exclude, 줄 인덱스와 fingerprint로 중복 합치기, 길이 상한. 규칙은 설정 파일
- 리댁션. 호스트명, IP, 계정, 토큰
- 이상 여부는 규칙으로 판정

## 3. 상세 구현 내용

### 3.1 `collect-logs`

**구현**

- 추가: 게이트 동사 `collect-logs <종류>`. 종류는 dnf, boot, secure, fail2ban
- 추가: `gostodian run`은 재부팅·재접속 뒤, 서비스 기동 전에 네 종류를 수집
- 유지: 셸 문자열 조립 없음. 종류는 고정 목록과 정확히 일치할 때만 통과

**완료**

- [x] 네 종류 로그가 실행 ID 단위로 수집됨
- [x] 목록 밖 종류는 거부되고 실행되지 않음

### 3.2 `resources`

**구현**

- 추가: 게이트 동사 `resources`. RAM, CPU, Storage
- 추가: 결과는 실행 이력과 수집 산출물에 남김

**완료**

- [x] RAM, CPU, Storage가 실행 ID 단위로 남음

### 3.3 부분 실패 계속

**구현**

- 추가: 한 종류 수집이 실패해도 나머지 종류는 계속
- 추가: 빠진 항목은 이력에 실패로 기록. 전체 점검을 그 이유로 즉시 중단하지 않음

**완료**

- [x] 일부 실패 후에도 나머지 수집이 이어짐
- [x] 빠진 항목이 이력에 남음

### 3.4 필터

**구현**

- 추가: 카테고리별 include/exclude. 부분 문자열. include가 있으면 그 중 하나를 포함한 줄만 남고, exclude에 걸리면 뺀다
- 추가: 같은 fingerprint(줄 내용의 SHA-256 앞 16자)는 첫 줄만 남기고, 줄 번호와 fingerprint를 그 줄 앞에 붙인다
- 추가: 길이 상한 `pipeline.filter.max_runes`. 비우면 262144글자. 넘치면 본문을 자르고 이력 단계에 `truncated`를 남긴다
- 결정: 규칙 위치는 로드맵이 가리킨 `Docs/Plan.md` 8.4가 아니라 점검 머신 설정 `pipeline.filter`. 종류는 dnf, boot, secure, fail2ban, resources

**완료**

- [x] 필터 골든 테스트 통과
- [x] 길이 상한을 넘는 내용은 잘림이 기록됨

### 3.5 리댁션

**구현**

- 추가: 필터 다음, 저장 전에 본문을 가림. 호스트명은 `[hostname]`, IP는 `[ip]`, 계정은 `[account]`, 토큰은 `[token]`
- 추가: syslog 시각 뒤의 호스트명, `for user`, `for <계정> from`, `USER=`는 설정 없이도 가림. `server.host`, `server.user`와 `pipeline.redact`의 이름을 본문에서 가림
- 유지: 개인키가 있으면 그 문자열 전체를 `[redacted]`. 웹훅 주소는 산출물과 알림에 없음
- 유지: 이력의 `host`, `user` 필드는 점검 대상 기록이라 남긴다

**완료**

- [x] 리댁션 골든 테스트 통과

### 3.6 규칙 판정

**구현**

- 추가: 필터·리댁션을 거친 본문을 `pipeline.rules`의 부분 문자열로 판정. 규칙은 점검 머신 설정
- 추가: 맞은 줄이 0이면 「이상 없음」. 하나 이상이면 「이상 있음」. 수집이 없으면 「수집 없음」이며 이상 없음으로 적지 않음
- 추가: 종류별 판정은 그 실행의 `logs/<실행ID>.json`에 남음. 판정만으로 기동을 멈추지 않음

**완료**

- [x] 매칭 0건은 「이상 없음」
- [x] 이상 판정이 실행 ID 단위로 남음
