# v0.4.0 (유지보수)

기준: `Doc/RoadMap_v1.md`의 v0.4.0  
출발점: v0.3.0  
일정: 수요일 26.10.28까지 2번·3번. 목요일 26.10.29에 4번.

## 1. 목표

점검 머신에서 `gostodian run` 한 번이 서비스 정지, `dnf` 갱신, 재부팅, 재접속, 역순 기동, 헬스체크를 순서대로 수행한다. 한 단계가 실패하면 거기서 멈추고 Discord로 알린다. 자동 롤백은 없다.

## 2. 구현 내용

- 서비스 정지 순서는 점검 머신 설정의 목록. 기동은 역순. 서비스 이름은 코드에 없음
- 게이트의 서비스 이름 허용 목록
- 동사 `stop <서비스>`, `start <서비스>`. 서비스마다 결과 확인
- 재부팅 뒤 자동 기동을 막는 정지
- 게이트 sudo 명령은 인자까지 고정. `docker`, `dnf *`, `systemd-run`은 sudoers에 없음
- 동사 `update`. `update-status`로 폴링
- 동사 `reboot`. `boot_id` 변경 확인. 제한 시간 초과 시 알림
- 동사 `health`. 컨테이너 기동 여부, 포트 Listening
- 모든 단계의 timeout. 실패 시 즉시 중단과 알림. 자동 롤백 없음

### 3.5 sudoers

**구현**

- 추가: 게이트의 sudo 명령은 경로와 인자가 한 줄로 고정. sudoers(그 계정에 허용된 관리자 명령 목록)에는 그 한 줄만 등록
- 유지: `docker`, `dnf *`, `systemd-run`은 그 목록에 없음
- 확인 필요: 로드맵 5번 sudoers. 고정 명령 목록
- 기본안: 서비스마다 `stop` 한 줄, `start` 한 줄. `update` 한 줄, `reboot` 한 줄. `update` 고정 명령이 내부에서 `systemd-run`(한 번 실행되고 끝나는 작업)으로 `dnf -y update`를 실행. sudoers에는 그 고정 명령만 등록
- 운영 준비: 홈랩 sudoers

**완료**

- [x] 게이트가 실행하는 sudo 명령은 등록된 고정 인자와 같음
- [x] `docker`, `dnf *`, `systemd-run`은 sudoers에 없음
