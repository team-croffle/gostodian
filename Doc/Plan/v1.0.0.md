# v1.0.0 (보고서·업로드·스케줄) — 초안

상태: **초안**. 로드맵 v1.0.0 범위를 옮겨 적은 것이다. 세부 구현은 확정 전이다. 확인이 덜 된 두 가지(AI 제공자, MinIO SSE)는 각 소절의 기본안이다. 스케줄은 점검 머신 타이머로 확정했다.

기준: `Doc/RoadMap_v1.md`의 v1.0.0  
출발점: v0.5.0  
일정: 26.11.2 (예정)

## 1. 목표

점검 머신에서 `gostodian run` 한 번이 보고서 초안을 만들고, 보고서·실행 로그·수집 아카이브를 같은 실행 ID로 MinIO에 올린다. AI가 실패하거나 MinIO가 안 떠 있어도 보고서와 알림은 남고, 수동 실행과 스케줄 실행이 같은 경로를 탄다.

## 2. 구현 내용

- AI 보고서 초안. 로그는 구조화된 필드, 경계 명시. AI 실패 시 고정 템플릿. LLM 출력은 실행 대상 아님
- MinIO 업로드. `reports/` 보고서, `logs/` 실행 로그, `collects/` 수집 아카이브. MinIO 재기동·헬스체크 통과 후에만
- SSE, PutObject 전용 키. 버킷과 프리픽스는 설정
- 업로드 실패 시 로컬 보존과 알림
- 게이트 거부 로그는 보고서. 거부 시 별도 알림
- Discord 완료 알림에 판정 요약과 보고서 위치
- 스케줄 실행은 점검 머신 타이머가 `gostodian run`을 한 번 실행. 상시 프로세스 스케줄러는 두지 않음. 수동 실행은 유지

## 3. 상세 구현 내용

### 3.1 AI 보고서 초안

**구현**

- 추가: 실행 ID로 로컬 보고서 초안. 로그는 구조화된 필드와 경계
- 추가: AI 호출 실패 시 고정 템플릿으로 그 보고서
- 유지: LLM 출력은 실행 대상 아님. 시크릿 본문은 보고서·알림에 없음
- 유지: 키 본문은 `secrets.ai_api_key_file`. env에는 경로만
- 확인 필요: 로드맵 5번 AI 제공자. 사용할 API
- 기본안: API 주소와 모델 이름은 점검 머신 설정. 코드에 제공자 이름을 두지 않음

**완료**

- [ ] AI 실패 시에도 보고서가 남음
- [ ] LLM 출력은 실행되지 않음
- [ ] 보고서에 시크릿 본문과 원문 로그의 가리지 않은 비밀 없음

### 3.2 MinIO 업로드

**구현**

- 추가: `reports/` 보고서, `logs/` 실행 로그, `collects/` 수집 아카이브
- 추가: 세 산출물은 같은 실행 ID
- 추가: 업로드는 역순 기동과 `health` 성공 뒤. 그 전에는 로컬만
- 유지: 서비스 이름은 코드에 없음. MinIO 이름도 점검 머신 설정의 목록

**완료**

- [ ] 보고서·실행 로그·수집 아카이브는 같은 실행 ID로 업로드
- [ ] `health` 성공 전에 업로드 없음

### 3.3 SSE와 PutObject 전용 키

**구현**

- 유지: `secrets.s3_access_key_file`, `secrets.s3_secret_key_file`. env에는 경로만
- 추가: 클라이언트 호출은 PutObject만
- 추가: 버킷과 프리픽스는 점검 머신 설정
- 확인 필요: 로드맵 5번 MinIO SSE. KMS 설정 필요 여부
- 기본안: SSE-S3(버킷 기본 암호화)만 가정. 클라이언트 KMS 키는 설정에 없음
- 운영 준비: 그 키의 권한을 PutObject로 제한

**완료**

- [ ] 업로드 호출은 PutObject만
- [ ] 키 본문은 파일. env와 보고서·알림에는 없음
- [ ] KMS 키 없이 SSE-S3로 업로드

### 3.4 업로드 실패

**구현**

- 추가: MinIO 미기동 또는 업로드 실패 시 산출물은 로컬 유지
- 추가: 그 사실은 Discord 알림
- 유지: 자동 롤백 없음. 업로드 실패가 이미 끝난 기동을 되돌리지 않음

**완료**

- [ ] MinIO 미기동 시 산출물은 로컬, 알림
- [ ] 업로드 실패 뒤에도 로컬 파일은 남음

### 3.5 게이트 거부

**구현**

- 추가: 이번 실행에서 게이트가 거부한 기록은 보고서의 한 필드. 출처는 실행 이력
- 추가: 거부가 있으면 완료 알림과 별도 Discord 알림
- 유지: 그 알림에 원문 로그와 웹훅 주소 없음

**완료**

- [ ] 거부 기록이 보고서에 남음
- [ ] 거부 알림은 완료 알림과 별도
- [ ] 거부 알림에 원문 로그와 웹훅 주소 없음

### 3.6 Discord 완료 알림

**구현**

- 수정: 완료 알림에 판정 요약과 보고서 위치
- 유지: 점검 시작·실패·접속 실패 알림. 원문 로그와 웹훅 주소 없음
- 유지: 전송 실패는 로컬 이력만. 점검 결과를 바꾸지 않음

**완료**

- [ ] 완료 알림에 판정 요약과 보고서 위치
- [ ] AI 실패 시에도 알림
- [ ] 메시지에 원문 로그와 웹훅 주소 없음

### 3.7 스케줄

**구현**

- 유지: 수동 `gostodian run`
- 확정: 점검 머신 타이머(systemd timer 또는 cron)가 OS 시계 기준으로 `gostodian run`을 한 번 실행. 상시 프로세스 안의 스케줄러는 두지 않음
- 추가: 스케줄 실행과 수동 실행은 같은 점검 경로. 스케줄 시각·유닛은 코드가 아니라 점검 머신 운영 설정

**완료**

- [ ] 스케줄로 한 번 이상 끝까지 실행
- [ ] 수동 `gostodian run`은 유지

## 4. 전체 테스트

v0.4.0, v0.5.0, v1.0.0 구현이 끝난 뒤에 한다. 버전마다 점검 창을 나누지 않는다. 홈랩에는 별도 저장소의 `gostodian-svc`가 `/usr/local/libexec/gostodian-svc`에 있어야 한다. v0.5.0에 있던 실서버 확인도 여기로 옮겼다.

### 4.1 한 번의 점검

수동 `gostodian run` 한 번으로 유지보수, 수집, 판정, 보고서, 업로드를 본다.

**대상**

- v0.4.0 정지, `update`, 재부팅, 역순 기동, `health`
- v0.5.0 수집, 필터, 리댁션, 규칙 판정
- v1.0.0 보고서, MinIO 업로드, Discord 완료 알림

**완료**

- [ ] 순서는 정지 → `update` → `reboot` → 재접속 → 수집 → 역순 기동 → `health` → 보고서 → 업로드
- [ ] 설정 목록 순서로 정지, 역순으로 기동. 정지 뒤 재부팅해도 대상 서비스는 올라오지 않음
- [ ] `update` 진행이 `update-status`로 이력. `boot_id`가 바뀐 뒤에 기동
- [ ] 재부팅·재접속 뒤, 서비스 기동 전에 `dnf`, `boot`, `secure`, `fail2ban`과 RAM, CPU, Storage가 실행 ID 단위로 수집됨
- [ ] 허용 목록 밖 이름과 추가 인자는 거부되고 실행되지 않음. sudo 명령은 등록된 고정 인자와 같음. `docker`, `dnf *`, `systemd-run`은 sudoers에 없음
- [ ] `stop`, `start`, `health` 결과가 이력
- [ ] 수집 원문 일부(타임스탬프, 여러 줄 스택트레이스 포함)로 필터·리댁션을 다시 확인. 어긋나면 픽스처와 규칙을 그 원문에 맞춤
- [ ] 길이 상한을 넘는 내용은 잘림이 기록됨
- [ ] 매칭 0건 카테고리는 「이상 없음」. 판정은 실행 ID 단위
- [ ] 보고서, 실행 로그, 수집 아카이브는 같은 실행 ID로 MinIO 업로드
- [ ] 완료 알림에 판정 요약과 보고서 위치. 원문 로그와 웹훅 주소 없음

### 4.2 성공 실행에 넣지 못하는 경우

전체 테스트 안에서 따로 본다. 버전을 나눠 먼저 끝내지 않는다.

**완료**

- [ ] `update` 실패는 그 단계에서 중단. 수집이 아닌 중간 실패는 다음 단계로 가지 않고 알림
- [ ] `boot_id`가 불변이거나 제한 시간 안에 돌아오지 않으면 실패와 알림
- [ ] 일부 수집 실패 시 빠진 항목만 기록되고 나머지는 남음. 빠진 종류는 「수집 없음」
- [ ] AI 실패 시에도 보고서와 알림. LLM 출력은 실행되지 않음
- [ ] MinIO 미기동 시 산출물은 로컬, 알림
- [ ] 게이트 거부 기록은 보고서. 거부 알림은 완료 알림과 별도
- [ ] 스케줄로 한 번 이상 끝까지 실행. 수동 `gostodian run`은 그대로
