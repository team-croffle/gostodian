# v0.1.0 (접속)

기준: `Doc/RoadMap_v1.md`의 v0.1.0  
출발점: 지금 코드 v0.0.1

## 1. 목표

점검 머신에서 `gostodian run`을 한 번 실행하면 SSH로 홈랩에 붙어 결과가 이력에 남는다. 홈랩이 꺼져 있거나 VPN이 끊기면 실패 종류가 이력에 남는다. 키 파일이 있으면 `key init`은 키를 바꾸지 않는다.

## 2. 구현 내용

- `gostodian run`: 수동 실행. 컨테이너는 `docker compose run --rm gostodian run`
- 시크릿 본문은 `secrets/` 파일(컨테이너는 `/run/secrets`). env에는 경로만
- `gostodian key init`: 키 파일 없을 때만 ed25519 키 생성, 공개키·fingerprint 출력. 인증 실패 시 재생성 없음
- 호스트 키는 `knownhosts.New`로 고정
- 접속 실패 분류에 호스트 키 불일치, `vpn_required` 추가
- 실행 이력은 볼륨

## 3. 상세 구현 내용

### 3.1 `gostodian run`

**구현**

- `cmd/gostodian`의 서브커맨드 `exec` → `run`. 플래그는 유지: `--config`, `--log-dir`
- 동작은 지금 `exec`와 같음. 설정 로드 → 이력 오픈 → `internal/ssh`의 `Run`으로 `/usr/local/bin/gostodian-agent` 실행 → 표준 출력·이력 기록
- 사용법 문구의 `exec` → `run`
- `compose.yaml`의 `restart: unless-stopped` → `no`. `up`으로 띄워도 종료 후 재시작 루프 없음
- 실행 예: `docker compose run --rm gostodian run`. `ENTRYPOINT` 뒤에 `run`이 붙는 형태
- 게이트 동사, Discord는 이 버전 범위 밖

**완료**

- [x] `gostodian run` 한 번에 SSH 결과 또는 접속 실패가 이력에 기록
- [x] `gostodian exec`는 사용법 오류
- [x] `docker compose run --rm gostodian run`은 컨테이너 1회 실행 후 종료
- [x] `docker compose up` 후에도 재시작 반복 없음

### 3.2 시크릿 파일

**구현**

- 유지: SSH 개인키·`known_hosts` 경로는 YAML. 컨테이너에서는 `GOSTODIAN_SSH_KEY_FILE`, `GOSTODIAN_KNOWN_HOSTS_FILE`이 `/run/secrets/...`로 덮어씀. env 값은 경로만
- 유지: 키 본문은 `internal/ssh`가 파일에서 읽음. 로그·에러 문자열에 본문 없음 (`internal/runlog`의 `PRIVATE KEY` 마스킹 유지)
- 이 버전에서 읽는 시크릿은 SSH 개인키와 `known_hosts`만. AI·S3·Discord 키 파일은 마운트만 유지하고 읽지 않음
- `key init`이 만드는 파일 경로는 설정의 `ssh.identity_file`. 개인키는 표준 출력에 없음

**완료**

- [x] 컨테이너 안에서 키·`known_hosts` 경로가 `/run/secrets` 쪽
- [x] 프로세스 환경 변수에 키 본문·웹훅 URL 없음
- [x] 접속 실패 로그에 개인키 본문 없음

### 3.3 `key init`

**구현**

- 서브커맨드 `gostodian key init [--config PATH]`
- `ssh.identity_file`이 없으면 ed25519 키 생성, 권한 `0600`, 공개키와 SHA256 fingerprint를 표준 출력 후 종료
- 파일이 이미 있으면 생성·덮어쓰기 없이 종료 코드 0, fingerprint만 출력
- 파일은 있으나 파싱 실패 또는 권한이 `0600`이 아니면 생성하지 않고 에러 후 종료
- `run`의 인증 실패(`auth_failed`) 경로에서는 `key init` 호출 없음
- 테스트: 키 있음 → 파일 바이트 불변. 키 없음 → 생성 후 공개키 한 줄

**완료**

- [x] 키 파일 없을 때만 생성, 공개키·fingerprint 출력
- [x] 키 파일 있으면 내용 불변
- [x] 파싱 실패·권한 오류 시 재생성 없음
- [x] 인증 실패 뒤 키 파일이 바뀌지 않음

### 3.4 호스트 키 고정

**구현**

- 유지: `internal/ssh`는 `knownhosts.New`만 사용. `ssh.InsecureIgnoreHostKey` 없음
- 불일치는 3.5의 `host_key_mismatch`로 넘김. 검증을 끄는 분기는 없음
- 홈랩을 재설치한 경우의 대응은 `secrets/known_hosts` 갱신

**완료**

- [x] 접속 코드 경로에 `InsecureIgnoreHostKey` 없음
- [x] `known_hosts`와 다른 호스트 키는 접속 실패. 이력의 분류는 `host_key_mismatch`

### 3.5 접속 실패 분류

**구현**

- 유지: `auth_failed`, `host_unreachable` (`internal/ssh`, `cmd/gostodian`의 `errorClass`)
- 추가: `knownhosts.KeyError` → `host_key_mismatch`. 지금처럼 원문 에러만 반환하지 않음
- 추가: `vpn_required`. 판단 기준은 로드맵에서 미정. 기본안은 설정의 `vpn.interface`(예: `wg0`)
  - 값이 있으면 다이얼 전에 그 인터페이스가 올라와 있는지 확인. 없거나 down이면 SSH 시도 없이 `vpn_required`
  - 값이 비어 있으면 검사 생략 (같은 LAN에서 개발할 때)
- 네 분류 모두 이력 `class`에 기록. 호스트 키 불일치를 `host_unreachable`에 넣지 않음
- 단위 테스트는 SSH를 흉내 냄. 실서버 확인은 읽기 전용 접속만

**완료**

- [x] 인증 거부 → `auth_failed`
- [x] 타임아웃·연결 거부·DNS 실패 → `host_unreachable`
- [x] 호스트 키 불일치 → `host_key_mismatch`
- [x] `vpn.interface`가 내려가 있으면 SSH 없이 `vpn_required`
- [x] `vpn.interface`가 비어 있으면 VPN 검사 없이 다이얼

### 3.6 이력 볼륨

**구현**

- 유지: `internal/runlog`. 실행 ID, jsonl, 종료 시 이력 JSON. 디렉터리 `0700`, 파일 `0600`
- 수정: 컨테이너의 `--log-dir`는 쓰기 가능한 마운트. 예: `./logs:/var/lib/gostodian` 와 `run --log-dir /var/lib/gostodian`
- `read_only: true` 유지. 쓸 수 있는 곳은 그 마운트뿐. 이미지 안 `logs/`에 쓰지 않음
- 마운트 소유는 컨테이너 사용자 `65532`가 쓸 수 있어야 함
- 로컬 실행의 기본 `--log-dir logs`는 유지

**완료**

- [x] `docker compose run --rm gostodian run --log-dir /var/lib/gostodian` 이후 호스트 `logs/`에 해당 실행의 jsonl과 이력 JSON
- [x] 컨테이너 루트 파일시스템에는 이력 파일 없음
- [x] 로컬 `gostodian run`의 기본 이력 위치는 `logs/`
