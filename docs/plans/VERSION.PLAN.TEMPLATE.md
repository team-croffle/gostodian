# 상세 구현 문서 템플릿

기준 로드맵: `docs/RoadMap.md`  
파일 위치: `docs/plans/vX.Y.Z.md` (버전당 하나)

이 문서는 버전별 상세 구현 파일을 쓸 때의 지침이다. 아래 뼈대를 복사해 해당 버전 내용만 채운다.

## 지침

- 범위는 로드맵에서 그 버전에 적힌 구현과 완료 기준만. 앞뒤 버전 내용은 넣지 않는다.
- 지금 코드(v0.0.1)에 이미 있으면 새로 만들 일 대신 **유지**로 적는다. 바꿀 것은 **수정**, 없는 것은 **추가**.
- 2번의 불릿 하나당 3번의 소절 하나. 번호는 3.1, 3.2, … 순서대로.
- 소절마다 **구현**과 **완료**를 둔다. 완료는 그 불릿만의 체크리스트.
- 버전 표기는 `v0.1.0 (접속)`. 하이픈으로 이름을 붙이지 않는다.
- 1번 목표만 문장으로 쓴다. 2번 이후는 `기동은 역순`, `점검 머신 설정의 목록으로 관리`처럼 명사구로 끝낸다.
- 확인이 덜 된 항목은 로드맵 5번의 해당 항목을 적고, 구현에 필요한 기본안을 같이 둔다.

## 뼈대

```markdown
# vX.Y.Z (범위 이름)

기준: `docs/RoadMap.md`의 해당 버전

## 1. 목표

(이 버전이 끝나면 무엇이 되는지. 문장 허용)

## 2. 구현 내용

- (로드맵의 구현 불릿)

## 3. 상세 구현 내용

### 3.1 (2번 첫 불릿의 이름)

**구현**

- (손댈 파일, 동작, 유지/수정/추가)

**완료**

- [ ] (이 불릿의 완료 조건)

### 3.2 (다음 불릿)
```
