# v1.0.0 (보고서·업로드·스케줄) — 초안

상태: **초안**. 로드맵 v1.0.0 범위를 옮겨 적은 것이다. 세부 구현은 확정 전이다. AI 보고서는 OpenAI 호환 Chat Completions + 파일 템플릿으로 확정했다. 스케줄은 점검 머신 타이머로 확정했다. MinIO SSE는 v1.0.0 범위에서 제외한다.

기준: `Doc/RoadMap_v1.md`의 v1.0.0  
출발점: v0.5.0  
일정: 26.11.2 (예정)

## 1. 목표

점검 머신에서 `gostodian run` 한 번이 보고서 초안을 만들고, 보고서·실행 로그·수집 아카이브를 같은 실행 ID로 MinIO에 올린다. AI가 실패하거나 MinIO가 안 떠 있어도 보고서와 알림은 남고, 수동 실행과 스케줄 실행이 같은 경로를 탄다.

## 2. 구현 내용

- AI 보고서 초안. 입력은 실행 ID·필터·리댁션된 로그·(템플릿 변경 시) 템플릿. 형식은 `templates/report_template.md`. AI 실패 시 같은 파일로 로컬 채움. LLM 출력은 실행하지 않음
- MinIO 업로드. `reports/` 보고서, `logs/` 실행 로그, `collects/` 수집 아카이브. MinIO 재기동·헬스체크 통과 후에만
- PutObject 전용 키. 버킷과 프리픽스는 설정
- 업로드 실패 시 로컬 보존과 알림
- 게이트 거부 로그는 보고서. 거부 시 별도 알림
- Discord 완료 알림에 판정 요약과 보고서 위치
- 스케줄 실행은 점검 머신 타이머가 `gostodian run`을 한 번 실행. 상시 프로세스 스케줄러는 두지 않음. 수동 실행은 유지

## 3. 상세 구현 내용

### 3.1 AI 보고서 초안

**구현**

- 추가: 실행 ID로 로컬 보고서 초안. 산출물 경로는 `logs/reports/<실행ID>.md` (또는 동등한 로컬 reports 경로)
- 추가: 보고서 뼈대는 내장하지 않음. 파일 `templates/report_template.md`(설정 `report.template_file`)을 따른다. AI 성공·실패 모두 이 형식을 목표로 함
- 추가: 템플릿 파일의 SHA-256을 직전 성공 실행과 비교한다. 해시 상태 파일은 `logs/report_template.sha256`(또는 설정 가능 경로)
  - 변경·추가·첫 실행: 요청에 템플릿 전문을 넣고, 「이전 형식 캐시를 쓰지 말고 이 템플릿만 따를 것」을 명시
  - 동일: 템플릿 전문은 넣지 않고 해시만 넣으며, 「템플릿 변경 없음. 기존과 동일한 섹션 구조로 작성」을 명시. (API 쪽 프롬프트 캐시가 있으면 그대로 재사용)
- 추가: AI 입력은 JSON에 가깝게 구성. 필드: `run_id`, `filtered_logs`(종류별 필터·리댁션 후 본문), `template_changed`, `template_sha256`, `template_markdown`(변경·첫 실행일 때만)
- 추가: HTTP는 OpenAI 호환 Chat Completions 한 종류. `POST {report.api_url}/chat/completions`, `model`, `messages`, `Authorization: Bearer` + `secrets.ai_api_key_file`. 코드에 제공자 이름 분기 없음
- 확정(운영): 기본 예시는 Claude 쓰기 쉬운 쪽. example의 `report.api_url` / `report.model`은 Anthropic OpenAI 호환 엔드포인트와 Claude 모델 이름을 가정. 실제 값만 점검 머신 설정에서 고침
- 추가: 시스템(또는 고정 선두) 메시지는 Claude에 맞춰 짧게. 역할=보고서 초안 작성, 템플릿 준수, 없는 사실은 추측하지 않음, 출력은 보고서 마크다운만
- 추가: AI 실패 시 같은 `report_template.md`에 실행 ID·판정·수집 요약만 기계적으로 채운 보고서를 남김. Discord 완료 알림은 유지
- 유지: LLM이 돌려준 텍스트는 파일로만 저장. 셸·게이트·스크립트로 실행하지 않음. 시크릿 본문은 보고서·알림에 없음
- 유지: 키 본문은 `secrets.ai_api_key_file`. env에는 경로만

**설정 키 (`report`)**

| 키 | 기본(설계) | 의미 |
| --- | --- | --- |
| `report.api_url` | (필수, example에 Claude 호환 base) | Chat Completions base URL. 끝의 `/chat/completions`는 코드가 붙이거나 문서에 명시 |
| `report.model` | (필수) | 모델 이름. 예: Claude 계열 |
| `report.template_file` | `templates/report_template.md` | 보고서 템플릿 경로. 내장 문구 없음 |
| `report.timeout` | `120s` | AI HTTP 한도 |
| `report.max_input_runes` | `48000` | AI에 넣는 `filtered_logs` 총 글자 상한. 넘치면 종류별로 잘라 `truncated` 기록 |
| `report.max_output_tokens` | `8192` | 응답 토큰 상한(요청 필드) |
| `report.template_hash_file` | `logs/report_template.sha256` | 직전 템플릿 해시 |

**실패 조건 → 템플릿 로컬 채움**

- `report.template_file` 없음·읽기 실패
- `report.api_url` / `report.model` 비어 있음
- `secrets.ai_api_key_file` 없음·비어 있음·읽기 실패
- 연결 실패, `report.timeout` 초과
- HTTP 상태 2xx 아님(401/403/429/5xx 포함)
- 응답 JSON 파싱 실패, `choices`·assistant `content` 없음·공백만
- 응답이 템플릿 필수 뼈대와 무관(최소한 `#` 제목 또는 `1. 개요` 없음)하면 실패로 보고 로컬 채움
- 입력이 `max_input_runes`로 잘려도 호출은 시도. 호출 자체가 위 조건에 해당하면 로컬 채움

**완료**

- [ ] AI 실패 시에도 `report_template.md` 형식으로 보고서가 남음
- [ ] 템플릿 파일 변경 시 요청에 전문·캐시 초기화 지시가 포함됨. 미변경 시 동일 형식 지시
- [ ] LLM 출력은 실행되지 않음
- [ ] 보고서에 시크릿 본문과 원문 로그의 가리지 않은 비밀 없음

## 4. 전체 테스트

v0.4.0, v0.5.0, v1.0.0 구현이 끝난 뒤에 한다. 버전마다 점검 창을 나누지 않는다. 홈랩에는 별도 저장소의 `gostodian-svc`가 `/usr/local/libexec/gostodian-svc`에 있어야 한다. v0.5.0에 있던 실서버 확인도 여기로 옮겼다.

### 4.1 한 번의 점검

수동 `gostodian run` 한 번으로 유지보수, 수집, 판정, 보고서, 업로드를 본다.

**대상**

- v0.4.0 정지, `update`, 재부팅, 역순 기동, `health`
- v0.5.0 수집, 필터, 리댁션, 규칙 판정
- v1.0.0 보고서, MinIO 업로드, Discord 완료 알림

**완료**

- [ ] 순서는 정지 → `update` → `reboot` → 재접속 → 수집 → 역순 기동 → `health` → 보고서 → 업로드
- [ ] 설정 목록 순서로 정지, 역순으로 기동. 정지 뒤 재부팅해도 대상 서비스는 올라오지 않음
- [ ] `update` 진행이 `update-status`로 이력. `boot_id`가 바뀐 뒤에 기동
- [ ] 재부팅·재접속 뒤, 서비스 기동 전에 `dnf`, `boot`, `secure`, `fail2ban`과 RAM, CPU, Storage가 실행 ID 단위로 수집됨
- [ ] 허용 목록 밖 이름과 추가 인자는 거부되고 실행되지 않음. sudo 명령은 등록된 고정 인자와 같음. `docker`, `dnf *`, `systemd-run`은 sudoers에 없음
- [ ] `stop`, `start`, `health` 결과가 이력
- [ ] 수집 원문 일부(타임스탬프, 여러 줄 스택트레이스 포함)로 필터·리댁션을 다시 확인. 어긋나면 픽스처와 규칙을 그 원문에 맞춤
- [ ] 길이 상한을 넘는 내용은 잘림이 기록됨
- [ ] 매칭 0건 카테고리는 「이상 없음」. 판정은 실행 ID 단위
- [ ] 보고서, 실행 로그, 수집 아카이브는 같은 실행 ID로 MinIO 업로드
- [ ] 완료 알림에 판정 요약과 보고서 위치. 원문 로그와 웹훅 주소 없음

### 4.2 성공 실행에 넣지 못하는 경우

전체 테스트 안에서 따로 본다. 버전을 나눠 먼저 끝내지 않는다.

**완료**

- [ ] `update` 실패는 그 단계에서 중단. 수집이 아닌 중간 실패는 다음 단계로 가지 않고 알림
- [ ] `boot_id`가 불변이거나 제한 시간 안에 돌아오지 않으면 실패와 알림
- [ ] 일부 수집 실패 시 빠진 항목만 기록되고 나머지는 남음. 빠진 종류는 「수집 없음」
- [ ] AI 실패 시에도 보고서와 알림. LLM 출력은 실행되지 않음
- [ ] MinIO 미기동 시 산출물은 로컬, 알림
- [ ] 게이트 거부 기록은 보고서. 거부 알림은 완료 알림과 별도
- [ ] 스케줄로 한 번 이상 끝까지 실행. 수동 `gostodian run`은 그대로
